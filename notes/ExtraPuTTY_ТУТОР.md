# ExtraPuTTY — полное руководство

## О документе

ExtraPuTTY — терминальный клиент для Windows, созданный как расширение PuTTY. Он сохраняет привычную модель сессий PuTTY, но добавляет функции, полезные для автоматизации, лабораторной работы, embedded-разработки и обслуживания оборудования: передачу файлов по XMODEM/YMODEM/ZMODEM, FTP/TFTP/SCP, Lua scripting, автоматическое переподключение, последовательности команд, session manager, переносимую конфигурацию, Win32/TestStand API, PuTTYcmdSender и другие расширения.

Документ описывает ExtraPuTTY как самостоятельный инструмент. В конце отдельно приведены два раздела по применению с BE-U1000.

> Важно: официальная страница проекта SourceForge указывает, что ExtraPuTTY основан на PuTTY 0.67, а последнее обновление проекта датировано 2016 годом. Для локальной работы с UART, XMODEM и лабораторным оборудованием это не мешает использовать программу, но для современных SSH-соединений с недоверенными сетями разумнее использовать поддерживаемый современный клиент — актуальный PuTTY или OpenSSH.

# 1. Что такое ExtraPuTTY

ExtraPuTTY — fork PuTTY для Windows с дополнительными средствами автоматизации и передачи файлов.

Базовая идея:

```text
ExtraPuTTY
├── терминал
├── сетевые подключения
├── serial / COM
├── сохранённые сессии
├── передача файлов
├── автоматизация
└── интеграция с внешними инструментами
```

В embedded-разработке ExtraPuTTY часто используют как:

```text
USB-UART
→ COM-порт Windows
→ ExtraPuTTY
→ терминал микроконтроллера
```

В сетевой эксплуатации:

```text
ПК
→ SSH/Telnet/Raw
→ удалённое оборудование
```

В производственных стендах:

```text
TestStand / Win32 API / Lua
→ ExtraPuTTY
→ устройство
→ автоматическая последовательность команд
```

# 2. Чем ExtraPuTTY отличается от PuTTY

PuTTY — терминальный клиент. ExtraPuTTY добавляет к нему функции, ориентированные на автоматизацию и передачу файлов.

По официальной странице проекта ExtraPuTTY заявлены:

- Lua scripting;
- интеграция PuTTY Session Manager;
- portable-использование;
- последовательности команд;
- хранение конфигурации в файловой структуре вместо обязательной зависимости от Registry;
- Win32/TestStand API;
- YMODEM;
- XMODEM;
- ZMODEM;
- FTP;
- TFTP;
- SCP;
- HyperLink;
- интеграция возможностей PuTTYcyg;
- меню и status bar в терминальном окне;
- shortcuts для предопределённых команд;
- keyboard shortcuts;
- PuTTYcmdSender для отправки команд нескольким окнам.

Именно поддержка XMODEM/YMODEM/ZMODEM делает ExtraPuTTY особенно удобным для загрузчиков микроконтроллеров и старого промышленного оборудования.

# 7. Сессии и профили

Сессия — сохранённый набор настроек.

Например:

```text
имя: MCU_UART
тип: Serial
порт: COM9
скорость: 115200
8N1
flow control: None
```

Или:

```text
имя: ROUTER
тип: SSH
host: 192.168.1.10
port: 22
```

## Сохранение

1. Настроить соединение.
2. Перейти в `Session`.
3. Ввести имя.
4. Нажать `Save`.

## Загрузка

1. Выбрать имя из списка.
2. Нажать `Load`.
3. Проверить изменяемые параметры.
4. Нажать `Open`.

Для Serial особенно важно проверять номер COM: Windows может назначить другой номер после смены USB-порта или драйвера.

Найти их можно:

```text
Диспетчер устройств
```

## Как определить порт

Надёжный способ:

```text
1. открыть Device Manager
2. посмотреть список COM
3. отключить устройство
4. посмотреть, что исчезло
5. подключить обратно
6. использовать появившийся COM
```

Если устройство создаёт несколько COM-портов, назначение каждого определяется документацией самого устройства.

# 10. Окончания строк и терминальное отображение

Терминалы используют управляющие символы:

```text
CR = \r
LF = \n
CRLF = \r\n
```

Типичный вывод embedded-программы:

```c
printf("Hello\r\n");
```

Если использовать только `\n`, конкретный терминал может отображать строки иначе.

Симптомы неправильной обработки:

```text
строки "уезжают" вправо
курсоры оказываются не в начале строки
текст накладывается
```

Настройки `Terminal` позволяют влиять на обработку терминальных управляющих последовательностей.

# 12. Автоматическое переподключение

ExtraPuTTY заявляет поддержку auto-reconnect.

Это полезно, когда соединение периодически теряется:

```text
сетевой разрыв
USB reconnect
перезапуск удалённого устройства
```

Типовой сценарий:

```text
устройство перезагрузилось
→ соединение пропало
→ ExtraPuTTY пробует восстановить сессию
```

Для загрузчиков Serial автоматическое переподключение следует использовать осторожно: после reset устройство может появляться как другой COM-порт или в другом режиме.

# 14. Последовательности команд

Проект заявляет sequencing of commands.

Смысл:

```text
command 1
→ command 2
→ command 3
```

Например:

```text
login
→ перейти в diagnostic mode
→ прочитать version
→ прочитать status
→ сохранить результат
```

Последовательности удобны при повторяемом обслуживании.

Необходимо учитывать:

- задержки ответа;
- приглашение командной строки;
- возможные ошибки;
- различия между версиями firmware.

# 21. XMODEM

XMODEM — простой блочный протокол передачи данных по последовательному каналу.

Типовая схема:

```text
Receiver
→ сообщает готовность

Sender
→ block 1
Receiver
→ ACK

Sender
→ block 2
Receiver
→ ACK

...
```

В вариантах с CRC получатель часто выдаёт:

```text
C
```

пока ждёт начало передачи.

## Где используется

```text
BootROM
bootloader
сетевое оборудование
старые embedded-системы
```

## ExtraPuTTY

Обычно:

```text
Files Transfer
→ XMODEM
→ Send
```

или соответствующий пункт Receive, если принимающей стороной является ПК.

## Ограничения

XMODEM сравнительно простой и медленный протокол. Он удобен не производительностью, а широкой поддержкой в загрузчиках.

---

# 22. YMODEM

YMODEM развивает идеи XMODEM.

Типичные отличия:

- передача имени файла;
- передача размера;
- поддержка пакетной передачи файлов в ряде реализаций;
- блочная схема с CRC.

Используется в некоторых загрузчиках и промышленном оборудовании.

Перед применением необходимо проверить, какую именно разновидность YMODEM поддерживает удалённое устройство.

---

# 23. ZMODEM

ZMODEM предназначен для более эффективной потоковой передачи.

Его преимущества в сравнении с XMODEM обычно связаны с:

- меньшим количеством ожиданий ACK на каждый блок;
- более эффективной работой на быстрых каналах;
- расширенными возможностями возобновления в поддерживающих реализациях.

Применяется в старых Unix/serial-средах и некоторых embedded-системах.

# 24. FTP, TFTP и SCP

## FTP

Классический сетевой протокол передачи файлов.

Подходит для оборудования, которое предоставляет FTP-сервер.

## TFTP

Очень простой UDP-протокол.

Часто встречается в:

```text
bootloader
PXE
сетевом оборудовании
firmware recovery
```

TFTP не предоставляет современных механизмов безопасности.

## SCP

Передача файлов поверх SSH.

Для современных систем важно учитывать, что ExtraPuTTY является старым проектом. Для чувствительных сетевых операций предпочтительнее актуальный OpenSSH/PuTTY.

# 25. Типовые сценарии и диагностика


## Сценарий: XMODEM upload в устройство

```text

→ XMODEM
→ Send

```

## Мусор в Serial

Проверить:

```text
baud rate
data bits
parity
stop bits
clock устройства
правильность COM
```

## Нет вывода

Проверить:

```text
порт существует?
драйвер установлен?
TX/RX/GND подключены?
порт не занят другой программой?
устройство действительно передаёт?
```

## Access denied

Чаще всего COM открыт другим приложением.

Закрыть:

```text
другой PuTTY
ExtraPuTTY
Tera Term
IDE Serial Monitor
Python serial script
```

## Неправильный COM

Определить методом отключения/подключения в Device Manager.

## XMODEM не стартует

Проверить:

```text
принимающая сторона действительно в режиме Receive?
выбран правильный XMODEM?
не выбран YMODEM/ZMODEM?
правильный COM?
```

## Безопасность

Особенно осторожно использовать команды:

```text
erase
format
factory reset
flash
bootloader update
```

Перед массовой автоматизацией сначала проверять сценарий на одном тестовом устройстве.

# 26. BE-U1000: UART и ExtraPuTTY

Этот раздел относится только к BE-U1000 и платам EVU-BA/EVU-LI.

Для UART0 используется профиль:

```text
115200 baud
8 data bits
No parity
1 stop bit
Flow control = None
```

Для EVU-BA при использовании `XS2 (JTAG UART0)` Windows может создать два COM-порта. В Quick Start для UART0 рекомендуется выбрать меньший номер.

Пример:

```text
COM9
COM12
```

использовать:

```text
COM9
```

Для обычного UART-вывода:

```text
ExtraPuTTY
→ Serial
→ COM9
→ 115200
→ Open
```

```text
UART printf example
```

# 27. BE-U1000: BootROM и XMODEM

Этот раздел относится только к BootROM BE-U1000.

## BootROM CLI

В UART boot mode можно войти в CLI удержанием:

```text
d
```

после RESET.

Ожидается приглашение:

```text
BU ROM[...]
@
```

## Загрузка в TCM

Команда BootROM:

```text
L
```

После появления `C`:

```text
Files Transfer
→ XMODEM
→ Send
→ program.bin
```

После передачи:

```text
@
```

Запуск:

```text
G
```

## eFlash

Официальный Quick Start приводит последовательность:

```text
14000018:1w
a0000000:22800:0:100m
:::101m
:::3L
```

Затем:

```text
Files Transfer
→ XMODEM
→ Send
```

Запуск из eFlash:

```text
a0000000g
```

> Команды eFlash изменяют энергонезависимую память. Для первого теста программы безопаснее использовать TCM.
